# Project rules — what is true of THIS repo (Layer 3 reference, project-owned)

The stage and lane contracts under `stages/` and `lanes/` are template-owned: byte-identical in
every pipeline repo, and carrying no repo's identity. Everything that is specific to this repo
lives in two project-owned files the sync never touches — `.icm/project.json` for the values a
script reads (name, docs path, archive paths, required checks and variables) and **this file**
for the rules a stage reads. A contract that says "see `_shared/project-rules.md`" means: the
answer is here, and it is this repo's own.

Fill each section in; a section that genuinely does not apply says so in one line.

## People and gates

- **The operator** — Jamie Nisbet: ticks **Spec approved** and **Ready to merge**, and merges
  every run's PR into `main` from GitHub.
- **Authors** — the estate's owner, through the answers to the two onboarding questionnaires in
  `.icm/onboarding/` (`business-details.md`, `functionality-features.md`) and direct requests;
  the operator themselves for the estate's own work. No rate, policy, capacity or contact detail
  is invented (`AGENTS.md` → Standing rules).
- **The client contact** — no client-facing report channel: `announce` cuts a GitHub Release
  and the operator relays to the owner. `REPORT_EMAIL_TO` is not set; add the email channel to
  `reporting` when the owner wants the release note directly.
- **UAT sign-off** — none: `uat` in `.icm/project.json` is undeclared, so a run ships to
  production on the merge. Declaring one is a `/setup` decision. Vercel SSO protection covers
  every non-custom domain on this project (`all_except_custom_domains`), so a UAT address would
  have to be a custom domain — `uat.vinecliff.jamienisbet.com` needs no DNS act
  (jamienisbet.com is on Vercel DNS).

## Knowledge

## The factory

- **Required CI checks** — none declared (`required_checks: []`): no Actions workflow runs on a
  PR. The build is Vercel's, read as the commit status `Vercel` through
  `deploy.projects[].status_context`. `db-migrate.yml` (check run `migrate`) runs on `main`
  only. The `tests/booking.test.ts` suite (`npm test`) runs in no CI today.
- **Deploy** — one product project, `vinecliff`, on the `kodominio` team; production is
  `https://vinecliff.jamienisbet.com`. The token is named in `project.json`. Every branch builds
  a preview (behind Vercel SSO).
- **Migrations** — `migrations` in `.icm/project.json`: `drizzle/`, generated by `npm run
  db:generate` as `NNNN_<name>.sql` with `meta/_journal.json` as the order of record — neither
  stamp form `check-migrations.sh` reads, so it answers SKIP. `out_of_order: false`: Drizzle
  applies the journal in sequence; two runs that both generated a migration are resolved by
  regenerating on the merged tree, never by hand-editing `idx`. Forward-only
  (`reversible: false`): a code revert must tolerate the newer schema. Applied to production by
  `.github/workflows/db-migrate.yml` (`scripts/migrate.ts`, Neon HTTP driver) on every push to
  `main`, from the `DATABASE_URL` Actions secret. `0001_seed_admin_user` and
  `0003_seed_booking_platform` seed data — **real bookings live in production**; never run
  `db:seed:demo` against it.
- **Environment surfaces** — `.env.example` at the root is the manifest (`DATABASE_URL`,
  `AUTH_SECRET` and the Vercel variables; `env.sh audit` reads it). Locally: `.env.local` with a
  branch's connection string, never production's.
- **Local feedback scripts** — not wired: `scripts/format.sh` and `scripts/lint.sh` report
  SKIP. No formatter in the repo; `next lint` is never run here.
- **The security gate** — `scripts/security-check.sh` runs before every commit in Build and
  before every lane's push. Not wired as a git hook (no Husky) — the stages call it. gitleaks:
  absent — the built-in patterns are the floor. `security.audit_command` is empty: the npm
  lockfile is audited.
- **The run's database** — `database.isolation: neon`: every run gets a Neon branch
  `run/<slug>`, a child of production, at `db-branch.sh <slug> up`, through the key
  `NEON_API_KEY` names in the shell (never in git). Until the key is exported, `db-branch.sh`
  answers SKIP and a session runs no migration locally.
- **The environments' databases** — Neon project `broad-lake-67509282` (`vinecliff`, Kodominio,
  aws-us-east-1, Postgres 17). Production is the `main` branch — **not protected** (an act owed).
  `neon.previews: none`: on 2026-09-23 the branch list holds `main` alone, so the Vercel
  integration's Preview-branching toggle is off and **every preview reads the Preview
  environment's `DATABASE_URL` — which can only be production's branch**. Turning it on (Vercel
  → Storage → the database → Connect Project → Deployments configuration → Preview) and then
  setting `neon.previews: vercel` is Jamie's call; migrations would then also need to reach
  previews at build. No `neon-cleanup.yaml` yet — it belongs with that switch.
- **Health endpoint** — `https://vinecliff.jamienisbet.com/`: the home page; a 200 means the
  site is up (it rendered 200 on 2026-09-23).
- **Archive** — the default `_done/` folders; served from nowhere.

## Reporting

- **Kinds → channels** — `announce` → github-release (the seeded default); `alert` → none —
  Vercel's own deployment-failed email is the alert; `economics` → none — icm-board's
  `run-economics.sh` writes it into the deal folder.
- **Who calls the hook** — `announce_from: session` — Release step 9 calls `report.sh announce`.
- **Changelog** — none; the PR's Summary line is the Release's body.
- **Workflows** — `db-migrate.yml` only. `release.yaml` is absent on purpose (`announce_from`
  is `session`); `labels.yaml` is absent on purpose (labels are projected by `new-run.sh` and
  Release). `.github/labels.yml` is the vocabulary (created on the repo 2026-09-23).

## Learned rules

*The constraints earlier runs paid for, appended before each close-out by two writers with one
shape: `.icm/scripts/retrospective.sh --apply` (at Release and at the end of every lane — one
line per error class a run fixed and flagged with `- rule:` in its `error.log`, or fixed again
after an earlier run already had, counted across the archive's `error.log`s) and
`.icm/scripts/run-pack.sh --sync-rules` (called by `close-out.sh` — the `## Learned rules` a run
wrote in its `FAILURE.md`: what no tool logged — a wrong assumption, a STOP, a skipped step).
Each line carries the run it was learned in. Build and the lanes read this section before their
first edit, with the same standing as the code rules. Edit or delete lines freely — this file is
the repo's own, never synced — and delete a line that reads as a slip rather than a constraint.*
